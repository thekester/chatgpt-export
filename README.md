# ChatGPT Markdown Export

A lightweight browser extension for archiving ChatGPT conversations in durable, reusable formats: Markdown, HTML, and ZIP.

Repository: [github.com/thekester/chatgpt-export](https://github.com/thekester/chatgpt-export)

It works with Chrome, Chromium, Edge, and Firefox without an intermediary server. Exports use the data available from the current ChatGPT session and preserve media, files, sources, and metadata whenever available.

## Features

- Export the current conversation or the accessible conversation history.
- Markdown, HTML, or both formats.
- Images, attachments, and files generated by ChatGPT.
- Web sources, file citations, tables, lists, code blocks, and rich content.
- Optional export of branches and regenerations.
- Self-contained Markdown (`*.embedded.md`) with resources embedded as MIME/Base64 Data URIs.
- Optional raw JSON, manifest, detected capabilities, and SHA-256 checksums.
- Incremental history export to skip unchanged conversations.
- Automatic splitting of large histories into multiple ZIP archives.
- ZIP64 support for large archives and archives containing more than 65,535 files.
- Local HTML index with full-text search, dates, projects, and message counts.
- DOM fallback for exporting the displayed conversation when the internal API is unavailable.
- Clean conversation output: empty turns are omitted and per-message model/timestamp lines are not added to Markdown or HTML.
- Readable turn separators: Markdown uses labeled quote markers and horizontal rules instead of `## User` or `## ChatGPT` sections.

## Quick installation

Ready-to-load builds are generated in `dist/` by the build script:

```bash
python build.py
```

The script creates builds for Chrome, Chromium, Edge, and Firefox. Each build also includes a versioned ZIP archive such as `chatgpt-export-chrome-0.6.1.zip`.

### Chrome, Chromium, and Edge

1. Open `chrome://extensions` or `edge://extensions`.
2. Enable **Developer mode**.
3. Click **Load unpacked**.
4. Select the matching folder in `dist/`.

### Firefox

1. Open `about:debugging#/runtime/this-firefox`.
2. Click **Load Temporary Add-on**.
3. Select `dist/firefox/manifest.json` or the Firefox archive.

Firefox uses `background.scripts`, while Chromium-based browsers use `background.service_worker`. `build.py` adapts the manifest automatically for each browser.

## Usage

1. Open `chatgpt.com` and sign in.
2. Open the extension from the browser toolbar.
3. Choose the format and export options.
4. Click **Export this conversation** or **Export all history**.

Settings are stored locally in the popup. History exports may produce multiple ZIP files when the configured maximum size is reached; the default is 1 GiB per archive.

### Main options

| Option | Effect |
| --- | --- |
| Markdown / HTML / Both | Selects the output format(s). |
| Save images | Downloads images when accessible. |
| Save attachments | Preserves documents and generated files. |
| Standard self-contained Markdown | Adds an `.embedded.md` file with resources encoded as Base64. |
| Modern Joplin Markdown | Creates a Joplin-safe ZIP with a `.modern.joplin.md` note and local resources. |
| Raw JSON data | Adds the source conversation JSON. |
| All branches | Includes available regenerations and branches. |
| Incremental export | Skips unchanged conversations from previous exports. |
| SHA-256 checksums | Adds file hashes to the manifest. |

When **Self-contained Markdown** is the only save option, the current conversation is downloaded directly as a single `.embedded.md` file, without a ZIP archive. A ZIP is created when another output or save option is enabled. **Save images** and **Save attachments and generated files** remain independent options and create their own `images/` and `files/` directories inside the archive.

The standard self-contained format keeps the export as plain Markdown with embedded Base64 resources. The Modern Joplin Markdown format adds the metadata fields supported by Joplin, including title, creation/update dates, source, author, and tags. It keeps images and files as local relative resources inside the ZIP instead of putting large Data URIs in the note, which is safer for Joplin.

Use **Modern Joplin Markdown** when importing into Joplin. Unzip the generated archive first, then import the extracted Markdown folder in Joplin. Joplin will store the note, images, and files in its own database, so the final note is self-contained in Joplin without external links. The standard `.embedded.md` format is intended for readers that handle large Base64 Data URIs reliably, not for large Joplin notes.

Access to all websites is optional. It is requested only when the extension needs to retrieve images or files hosted outside ChatGPT. Without this permission, the main export still works and preserves remote links when necessary.

## Export structure

Depending on the selected options, an archive may contain:

```text
export.zip
├── index.html
├── manifest.json
├── _capabilities.json
├── _errors.txt
├── conversations/
│   └── 2026-09-20_conversation-title/
│       ├── conversation.md
│       ├── conversation.html
│       ├── conversation.embedded.md
│       ├── metadata.json
│       ├── raw.json
│       ├── images/
│       └── files/
└── ...
```

Files are included only when relevant to the selected options or to the data actually available.

## Compatibility and fallbacks

ChatGPT’s internal endpoints are not public APIs and may vary by account, workspace, and deployment. The extension tests each capability independently: a `403` or `404` is recorded in `_capabilities.json`, then the export continues with the available data.

For the current conversation, if the internal JSON endpoint is unavailable, the extension rebuilds an export from the messages visible on the page. This fallback is less complete but still recovers the displayed content.

Files generated with `sandbox:` use multiple download endpoints. Standard, archived, Projects, and shared conversations are supported when the account exposes the corresponding endpoints.

## Development

The project requires neither Node.js nor a JavaScript compilation step. The Python build script assembles the sources, adapts the manifest, and creates ZIP archives.

```text
src/
├── background.js   # Downloads requiring host permissions
├── content.js      # ChatGPT access and export orchestration
├── render.js       # Markdown, HTML, and index rendering
└── zip.js          # Browser-side ZIP/ZIP64 generation
popup/
├── popup.html      # Configuration interface
└── popup.js
lib/
└── marked.umd.js   # Bundled Markdown renderer
```

Rebuild all distributions with:

```bash
python build.py
```

The `dist/` directory is recreated on every run.

## Privacy and limitations

- Exports are generated locally in the browser.
- The extension does not send data to a third-party service.
- Requests to ChatGPT use the session already open in the browser.
- External image requests are made only when the corresponding optional permission is granted.
- ChatGPT’s internal APIs may change without notice.
- The DOM fallback exports only the conversation currently displayed; it cannot replace API access for browsing the full history.
- Self-contained Markdown increases binary resource size by about 33% because of Base64 encoding. Some Markdown viewers may block `data:` URLs.

Private reasoning and hidden internal tool calls are not exported: only content displayed or exposed as conversation data is preserved.
